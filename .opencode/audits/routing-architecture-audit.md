# فحص معماري: نظام المسارات (Routing Architecture Audit)

- **التاريخ:** 2026-08-10
- **النطاق:** مسارات العرض `(viewer)` المتنافسة على «العمل الوسائطي» (media work): `/itemView/[type]/[id]` و `/player/[id]` و `/audio/[type]/[id]` و `/singer/[id]`
- **الحالة:** تقرير فحص فقط — **لم يُنفَّذ أي تعديل على الكود**

---

## 1. النموذج المفاهيمي للكيان (Conceptual Model)

المصدر الموثوق: `src/backend/db/schema.ts` + `src/lib/frontend/media-constants.ts`.

- **العمل (Work):** جدول واحد متعدد الأشكال `media_items`. كل فيلم / مسلسل / حلقة / ألبوم / أغنية / «مُنشد/مغنٍ» / مسرحية هو صف واحد في هذا الجدول، ومُعرَّف بـ `media_id` رقمي فريد هو **نطاق الأرقام الوحيد**.
- **التمييز النوعي:** عمود `type` هو المُصنِّف، و `parent_media_id` يبني الشجرة (ألبوم ← أغنية؛ مسلسل ← مواسم ← حلقات).
- **الملف القابل للتشغيل:** `media_files` — صف واحد لكل ورقة قابلة للتشغيل (حلقة/أغنية/ملف فيلم).
- **الأشخاص:** `media_people` — كيان الأشخاص مشتق من علاقة الجداول. **لا يوجد جدول «فنان» مستقل**؛ «المُنشد» هو **نوع من أنواع الوسائط** (جذر شجرة الألبوم ← الأغنية)، وليس دورًا في `media_people`.

نتيجة مباشرة: **أي معرّف وسائطي واحد = كيان واحد**. المسارات الأربعة أدناه كلها تخدم نفس الكيان (أو مجموعة من نفس الكيان)، وليست كيانات منفصلة.

## 2. تقييم المسارات الأربعة (تقييم مستقل لكل مسار)

### 2.1 `/itemView/[type]/[id]` — صفحة التفاصيل

- **الوظيفة الفعلية:** عرض تفاصيل العمل + الأقسام (المواسم/الأغاني) + `MediaActions`.
- **المعرف:** `media_id` من `useParams().id`؛ يُقرأ العمل بـ `useMediaById(id)`.
- **`[type]`:** جزء زائد عن الحاجة — المعرّف فريد عموميًا، والنوع موجود أصلًا في بيانات `media_items`، ولا يُستخدم المقطع في منطق الصفحة (لا تحقق ولا توجيه). مجرد مقطع زينة/SEO غير مُتحقَّق منه.
- **الرابط الوارد:** بطاقات `unified-card` و `media-card` عبر `buildMediaUrl`.
- **التقييم:** **صالح ومُستخدم** — هو مسار التفاصيل الفعلي. العيب الجوهري هو مقطع `[type]` الزائد.
- **التوصية:** RENAME (إسقاط `[type]`) — انظر القسم 8.

### 2.2 `/player/[id]` — صفحة المشغّل

- **الوظيفة الفعلية:** تشغيل «فيديو» فقط: `VideoPlayer` يعتمد على `streamUrl = /api/media/${id}/stream` (مسار API موجود ويعمل: `src/app/api/media/[id]/stream/route.ts`).
- **المعرف:** `media_id` (نفس نطاق itemView).
- **الرابط الوارد:** `MediaActions` «شاهد الآن» دائمًا → `/player/{media_id}` بغض النظر عن النوع، وزر الحلقة في أقسام المواسم → `/player/{episode_media_id}`.
- **التقييم:** **صالح ومُستخدم للفيديو** — مسار تشغيل نظيف أحادي المسؤولية. لكنه **غير واعٍ بالنوع**: لا يعرف الصوت، ولا يفحص `media.type`، و `VideoPlayer` يفترض فيديو.
- **التوصية:** KEEP مع إصلاح — انظر القسم 8.

### 2.3 `/audio/[type]/[id]` — صفحة تفاصيل الصوت مع تشغيل مدمج

- **الوظيفة المفترضة:** تفاصيل ألبوم/أغنية + شبكة أغاني + `AudioPlayer` مدمج.
- **المعرف:** `media_id` (نفس النطاق)؛ **مقطع `[type]` لا يُستخدم في منطق الصفحة أيضًا** — الصفحة تستشير `media.type` فقط.
- **الرابط الوارد:** `buildAudioUrl` و `buildMediaUrl` تُولّدان روابط `/audio/{type}/{media_id}` (مثال: `src/features/viewer/components/audio-player/types.ts`).
- **التقييم:** **تداخل زائد مع itemView** لنفس الكيان الصوتي (نفس المعرّف، نفس المورد). مسار هجين (تفاصيل + تشغيل) يكسر مبدأ المسؤولية الواحدة، ويفرض «صفحة صوت خاصة» غير مبرَّرة بنموذج البيانات الأحادي.
- **التوصية:** MERGE في مسار التفاصيل الموحّد — انظر القسم 8.

### 2.4 `/singer/[id]` — مسار يتيم

- **الوظيفة الفعلية:** `src/app/(viewer)/singer/[id]/page.tsx` يستورد `AudioPage` ويعيد توجيهها. **لا يوجد أي رابط داخل التطبيق يشير إليه** (بحث شامل: لا استخدام في `buildMediaUrl`/`buildAudioUrl`/`ROUTES`/أي مكوّن).
- **التقييم:** **مسار ميت** — ليس له مدخل من UI، واسمه يوحي بوجود كيان «فنان» مستقل لا وجود له في نموذج البيانات.
- **التوصية:** REMOVE — انظر القسم 8.

## 3. الفحص الفعلي للكود (وليس أسماء المجلدات)

### 3.1 الحالة الحرجة الحالية للشجرة (مهم — يجب معالجتها قبل أي إعادة تصميم)

البنية الفعلية الآن **لا تطابق** ما تصفه البنية المطلوبة ولا ما كان قائمًا عند آخر بناء ناجح:

1. **`src/features/viewer/pages/audio-page.tsx` غير موجود** في شجرة الملفات الحالية (مؤكد عبر `Read` و `glob` و `dir`).
2. **مجلد المسار `src/app/(viewer)/audio/[type]/[id]/` غير موجود** — لا يوجد مسار `/audio/...` أصلًا الآن.
3. **`src/app/(viewer)/singer/[id]/page.tsx` ما زال يستورد `@/features/viewer/pages/audio-page`** → استيراد معلَّق → **البناء سيفشل الآن** حتى لو لم نلمس أي شيء.
4. **`buildAudioUrl` / `buildMediaUrl` / `ROUTES.AUDIO` ما زالت تُولّد روابط `/audio/{type}/{id}`** → روابط ميتة.
5. **`AudioPlayer` يبث من `/api/stream/${id}`** (`audio-player.tsx:17`) → **لا يوجد مسار API بهذا الاسم** → تشغيل الصوت معطَّل (الفيديو يعمل عبر `/api/media/{id}/stream`).

ملاحظة: هذه الملفات كانت موجودة واجتازت بناءً ناجحًا (114 صفحة) في وقت سابق من نفس الجلسة؛ تغيّرت الشجرة بعد ذلك من خارج عملية هذا الفحص.

### 3.2 الوضع الفعلي للوصلات

| الرابط من | إلى | الحالة |
|---|---|---|
| `MediaActions` «شاهد الآن» | `/player/{id}` دائمًا | يعمل للفيديو / **خاطئ للصوت** |
| زر الحلقة في الأقسام | `/player/{episode_id}` | يعمل |
| `buildMediaUrl` (صوت) | `/audio/{type}/{id}` | **ميت الآن** (لا يوجد مسار) |
| `buildMediaUrl` (فيديو) | `/itemView/{type}/{id}` | يعمل |
| `buildAudioUrl` | `/audio/{type}/{id}` | **ميت الآن** |
| `hero.tsx` (fallback) | `/itemView/{typeLabel}/{mediaId}` | يعمل (مقطع type عشوائي غير مُتحقَّق) |
| بطاقات `unified-card` / `media-card` | `buildMediaUrl` | تابع للفوق |

## 4. نموذج البيانات (Data Model)

- **المورد الوحيد:** `media_items` (عمل واحد = معرّف واحد = مسار تفاصيل واحد مفاهيميًا).
- **التشغيل:** `media_files` عبر `media_id` → بث؛ **لا يوجد جدول منفصل للفنان/المُنشد**.
- **الفجوة في كتالوج الأنواع (نقاط يجب تسجيلها):**
  - `AUDIO_TYPES` في `audio-player/types.ts` مُعلَنة كمصدر وحيد للصوت — لكن `song` غير موجود في ترجمات `MEDIA_TYPES` (translate.ts) ولا في `ALLOWED_TYPES` الخاص بالإدارة.
  - `singer` غير موجود في `ALLOWED_TYPES` ولا في نموذج المكتبة (`library-form`).
  - `track` موجود في `AUDIO_TYPES` لكن ليس له ترجمة في `translate.ts`.
  - `audio_deen` ناقص من `MERGABLE_ROOT_TYPES` ومن محسِّن العناوين.

## 5. تدفق التشغيل (Playback Flow)

**مسار الفيديو (يعمل):**
بطاقة → `/itemView/{type}/{media_id}` → تفاصيل → «شاهد الآن» → `/player/{media_id}` → `VideoPlayer` → `/api/media/{id}/stream` (يعمل).

**مسار الحلقة (يعمل):**
تفاصيل مسلسل → أقسام المواسم → نقر حلقة → `/player/{episode_media_id}` → نفس مشغّل الفيديو.

**مسار الألبوم/الأغنية (معطَّل عند النقاط الحمراء):**
بطاقة → `/audio/{type}/{media_id}` (مسار مفقود حاليًا) → تفاصيل + شبكة أغانٍ → نقر أغنية → `/audio/song/{track_id}` (مسار مفقود) → `AudioPlayer` → `/api/stream/{id}` → **404**.

**خلل جوهري إضافي:** `MediaActions` «شاهد الآن» يوجّه **دائمًا** إلى `/player/{id}` حتى داخل صفحة صوت؛ الدالة `getPlayLabel` معرّفة لكن غير مستخدمة. فالصوت يصل إلى مشغّل فيديو (مسار يعمل لكن بمشغّل خاطئ).

## 6. تصميم الروابط (URL Design)

- **تكرار روابط لنفس المورد:** الأغنية نفسها متاحة نظريًا عبر `/audio/song/{id}` و `/player/{id}` و `/singer/{id}` و `/itemView/song/{id}` — حتى 4 روابط لكيان واحد → مشكلة canonical/SEO وتعميم لحالة «أيها الصحيح؟».
- **تصادم نطاقات المعرّف:** `/items/[id]` يستخدم `library_id` (حاوية مكتبة)، بينما `/itemView/[id]` و `/player/[id]` و `/audio/[id]` تستخدم `media_id`. النطاقان مختلفان لكن كلاهما يحمل اسم المقطع `[id]` — التباس في أمانة المسار.
- **`[type]` الزائد:** في `itemView` و `audio` غير مستخدم منطقيًا وغير مُتحقَّق → روابط مثل `/itemView/anything/123` صالحة بلا معنى.
- **تسمية غير قياسية:** `itemView` و `liveStream` (camelCase) بدل `item-view`/`live-stream` القياسية في App Router — تجميلي لكن ثابت الحال.
- **تعميق الروابط (Deep linking):** الفيديو يعمل؛ الصوت **مكسور حاليًا** (مسار + بث).

## 7. مقارنة بأفضل الممارسات

| البعد | الحالة | درجة |
|---|---|---|
| مسارات حسب الموارد (Resource routes) | لا — مسارات حسب «عرض/فعل» | ✗ |
| موارد متداخلة (Nested) | جزئيًا عبر `parent_media_id` لكن غير معبَّر عنه في المسارات | ~ |
| مقاطع ديناميكية | سليمة | ✓ |
| دلالات مسار متسقة | غير متسقة (itemView مقابل audio مقابل player) | ✗ |
| فصل مسار العرض عن مسار الفعل | مختلط (audio هجين؛ player فعلي) | ~ |
| رابط canonical واحد | مكسور (روابط متعددة للمورد) | ✗ |
| مسؤولية واحدة للمسار | منتهكة في audio ومكررة في itemView/audio | ✗ |

**التقييم الإجمالي: ~4/10.** مقبول للفيديو، إشكالي للصوت (مسار ميت + بث ميت + توجيه خاطئ من MediaActions).

## 8. القرار والبدائل (KEEP / MOVE / RENAME / MERGE / REMOVE)

### البديل أ (الحد الأدنى — بدون هجرة مسارات)
- حذف `/singer/[id]` نهائيًا وإسقاط استيراده (إصلاح البناء).
- حذف استيراد `audio-page` المفقود من أي مكان؛ إما إعادة إنشاء `audio-page` كصفحة تفاصيل صوت مع مشغّل مدمج تحت مسار واحد، أو دمج محتواها في صفحة التفاصيل الموحّدة.
- إبقاء `/player/[id]` كما هو، وجعله واعيًا بالنوع (صوت ↔ فيديو) وإصلاح بث الصوت إلى `/api/media/{id}/stream`.
- إسقاط مقطع `[type]` من `itemView` (يصبح `/item/[id]`) وتحديث كل مولّدي الروابط.

### البديل ب (موجه للموارد — الأنظف للـ SEO والـ canonical)
- `/items/[id]` تبقى حاوية المكتبة (أو تُعاد تسميتها `/libraries/[id]` لإنهاء تصادم `[id]`).
- `/item/[id]` — مسار التفاصيل **الوحيد** لكل الأنواع (يختار التخطيط حسب `media.type`: صوت ← شبكة أغانٍ + مشغّل مدمج؛ فيديو ← تفاصيل + أقسام).
- `/player/[id]` — مسار تشغيل واحد واعٍ بالنوع (أو `/item/[id]/play` لاحقًا).
- `/audio/*` و `/singer/*` و `/itemView/*` تُحذف، مع redirects من الروابط القديمة.

### البديل ج (تسلسل هرمي حسب الكيان)
- `/singer/[id]` تصبح «مركز مُنشد» حقيقيًا (ألبوماته) — **يتطلب أولًا** إنشاء كيان فنان مستقل في `media_people`/جدول خاص. لا يُنصح به الآن لأن نموذج البيانات لا يملك هذا الكيان.

### القرار المعتمد

| المسار | القرار | المبرّر |
|---|---|---|
| `/itemView/[type]/[id]` | **RENAME → `/item/[id]`** | مسار التفاصيل الشرعي؛ إسقاط `[type]` الزائد |
| `/player/[id]` | **KEEP** (بإصلاحات) | مسار تشغيل نظيف؛ جعله واعيًا بالنوع + إصلاح بث الصوت |
| `/audio/[type]/[id]` | **MERGE** → تفاصيل موحّدة بتخطيط صوتي | تداخل مع itemView؛ نفس المورد والمعرّف |
| `/singer/[id]` | **REMOVE** | مسار يتيم؛ لا رابط وارد؛ لا كيان «فنان» مستقل |

### المعمارية الموصى بها (Recommended Canonical Routing Architecture)

```
/                                  → الرئيسية
/sections, /sections/[id]          → المكتبات
/items/[libraryId]                 → مجموعة مكتبة (تُعاد تسميتها /libraries/[id] لاحقًا)
/item/[mediaId]                    → التفاصيل الموحّدة (كل الأنواع؛ الصوت بتخطيط خاص + مشغّل مدمج)
/player/[mediaId]                  → التشغيل (واعٍ بالنوع: فيديو/صوت)
/person/[id], /genre/[slug], /year/[year], /rating/[value], /certification/[cert] → دون تغيير
```

**خطوات التنفيذ المقترحة (تُنفَّذ لاحقًا بجلسة تنفيذ مستقلة — خارج هذا الفحص):**
1. إصلاح حالة الشجرة أولًا: معالجة الاستيراد المعلَّق في `singer/[id]/page.tsx` وروابط `/audio/*` الميتة وبث `/api/stream/*`.
2. توحيد مسار التفاصيل على `/item/[id]` مع تحديث `buildMediaUrl` و `ROUTES`.
3. جعل `/player/[id]` واعيًا بالنوع؛ إصلاح `MediaActions` لاستخدام `getPlayLabel`/النوع بدل التوجيه الأعمى.
4. إغلاق فجوات كتالوج الأنواع (song/track/singer في الترجمة ونماذج الإدارة).
5. أي دالة/مكوّن يُعدَّل أثناء التنفيذ يلتزم بمتطلب TSDoc (وثائق + TSDoc معًا).
