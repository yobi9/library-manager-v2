## الجلسة الثانية — إصلاح وميض الثيم الداكن في الوضع الفاتح (الجذر)

> بعد الجولة الأولى صار هناك **وميض داكن لحظي** يظهر للوضع الفاتح فقط عند دخول
> لوحة الإدارة. طلب المستخدم صراحةً: دراسة الوضع جيداً وتحديد مصدر الوميض **قبل**
> أي تعديلات. التشخيص اكتمل قراءةً فقط، ثم نُفّذ الإصلاح.

### السبب الجذري (مُثبَت بالكود)

1. **الخادم يعرض الداكن دائماً** — `getAdminThemeServerSnapshot()` في
   `src/app/admin/layout.tsx` ترجع الثابت `ADMIN_THEME_DEFAULT = "dark"`. الخادم لا
   يقرأ `localStorage` (قاعدة عزل تفضيل الثيم عن الخادم) → كل HTML الإدارة يبدأ بـ
   `data-theme="dark"`.
2. **لا سكربت «قبل الطلاء»** — الثيم العام لا يومض لأن `next-themes` يحقن سكربتاً
   مدمجاً يطبّق التفضيل على `<html>` قبل أول رسم؛ ثيم الإدارة لم يكن يملك ما يقابله.
3. **الانقلاب بعد الترطيب** — `useSyncExternalStore` يعيد قراءة `localStorage` بعد
   الترطيب → `dark` → `light`. ومزامنة `<body>` المضافة في الجولة الأولى كانت ترسم
   أولاً بلقطة الخادم (`dark`) ثم تنقلب — **ضخّمت الوميض** إلى كامل الشاشة.

**الناتج:** الوضع الفاتح فقط يرى: أول طلاء داكن ← بعد الترطيب فاتح. الوضع الداكن لا
يرى شيئاً لأن افتراضي الخادم يطابق تفضيله — مطابق تماماً لبلاغ المستخدم.

### الإصلاح (4 أجزاء — نفس نمط anti-flash الخاص بـ next-themes)

1. **سكربت مدمج مبكر** `ADMIN_THEME_SCRIPT` في `AdminLayout` (يُحقن قبل الغلاف):
   يُنفَّذ متزامناً أثناء تحليل HTML وقبل أول طلاء، يقرأ `admin_dashboard_theme` من
   `localStorage` ويطبّق `admin-layout` + `data-theme` على `<body>`. **نصّه يُبنى من
   ثابتَي `ADMIN_THEME_KEY`/`ADMIN_THEME_DEFAULT`** (مصدر الحقيقة الواحد).
2. **نقل توكينات CSS الإدارية إلى `<body>`** بدل غلاف React:
   - `body.admin-layout` (داكن) / `body.admin-layout[data-theme="light"]` (فاتح).
   - متغير `admin-dark` أصبح `:where(body.admin-layout:not([data-theme="light"]), ... *);`.
   - `[data-theme="light"] .admin-sunken` و`.admin-logo` → body-scoped؛
     `.admin-layout .admin-sunken/.admin-raised` بقيا كما هما (محدّدات سليل سليمة).
   - السبب: الثيم يُدار بأداة DOM لا يمسها React → لا تباين ترطيب ولا انقلاب.
3. **`suppressHydrationWarning` على `<body>`** في `src/app/layout.tsx` (مثل next-themes
   على `<html>`) حتى لا يعيد React ضبط السمات التي وضعها السكربت أثناء الترطيب.
4. **إعادة صياغة مزامنة `<body>`** في `AdminLayout`:
   - `useLayoutEffect` + `useRef` (`themeMountedRef`): تخطي أول تشغيل إذا سبق للسكربت
     إضافة `admin-layout` — لأن تأثير الترطيب الأول يمرر `theme` = لقطة الخادم
     (`dark`)، وبدون التخطي كان يلغي قيمة السكربت ثم يعيد الرسم داكن (نفس الوميض).
   - التطبيق على التنقل العميل (SPA) وعند تبديل الثيم قبل الرسم.
   - **تنظيف مستقل** `useEffect` (بلا اعتماديات): يُنفَّذ عند مغادرة `/admin` فقط،
     فلا تُحذف سمات body مؤقتاً عند كل تبديل ثيم (كان يسبب وميضاً إضافياً).
